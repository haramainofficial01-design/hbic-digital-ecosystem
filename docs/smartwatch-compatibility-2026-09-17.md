## Official references and decisions

- Wear OS Data Layer requires the phone and watch package names and signatures to match, and Google recommends an independent network path rather than relying on Data Layer as the primary network transport: <https://developer.android.com/training/wearables/data/overview>.
- Garmin Connect IQ supports Device Apps, Widgets/Glances, watch faces, BLE/mobile communication, and authenticated web services, but it is a separate Monkey C product with a device compatibility manifest: <https://developer.garmin.com/connect-iq/overview/> and <https://developer.garmin.com/connect-iq/user-experience-guidelines/developing-the-concepts/>.
- Huawei documents native HarmonyOS wearable development in ArkTS with DevEco Studio and AppGallery Connect distribution. This is not an Android/Wear OS package target: <https://developer.huawei.com/consumer/en/multidevice/wearables/get-started/>.
- Zepp OS defines Device App, Settings App, and Side Service architecture; the Side Service may fetch third-party services. Publication requires a console-issued appId matching the `.zab`: <https://docs.zepp.com/docs/guides/architecture/arc/> and <https://docs.zepp.com/docs/distribute/>.
- Fitbit's current platform terms still define Device, Companion, and Settings developer tools for supported Fitbit products and require an App Gallery distribution agreement. Since the public portal does not provide a reliable current model promise without account/device validation, HBIC support is deliberately not advertised: <https://dev.fitbit.com/new-developer/>.

## Packaging notes

- Wear OS uses `ca.hbic.calgary.app`, exactly matching the Android phone package. Google Play signing must sign both artifacts with the same app signing identity before Data Layer sync can be called production verified.
- Zepp OS output is structurally valid, but `app.appId = 1000000` is a development placeholder. It must be replaced by the appId assigned to HBIC in the Zepp developer console, rebuilt, tested in the official simulator and at least one representative physical watch, then submitted.
- Garmin, Huawei, and Fitbit cannot safely share a binary with Wear OS or Zepp OS. Each would require a separate implementation, store identity, simulator/device test plan, and ongoing maintenance budget.
